# 软件开发标书知识库（种子版 v1.0）

> 本知识库面向政务信息化、企业数字化、软件定制开发、系统集成类项目的投标工作。
> 供招标解析专家识别软件资质/技术标准/评分要求，供技术方案架构师和编写专家检索引用。
> 每条知识标注：适用场景、核心要求、标书响应要点、常见废标风险。

---

## 一、软件工程国家标准

### 1.1 GB/T 8567-2006《计算机软件文档编制规范》

**适用场景**：所有软件开发类项目，尤其是政府、国企、军工信息化项目。

| 文档类型 | 标书响应要点 |
|---------|-------------|
| 可行性研究报告 | 项目立项、技术经济分析 |
| 软件需求规格说明（SRS） | 功能/非功能需求、用例、接口需求 |
| 软件设计说明（SDD） | 总体设计、详细设计、数据库设计 |
| 软件测试计划/报告 | 测试策略、测试用例、缺陷管理 |
| 用户手册 | 操作说明、维护手册、培训材料 |

**常见评分点**：招标文件常要求"项目文档符合 GB/T 8567"，技术标书应明确列出将交付的 14 类文档清单。

### 1.2 GB/T 25000.51-2016《软件产品质量要求与评价（SQuaRE）》

| 质量特性 | 标书响应要点 |
|---------|-------------|
| 功能性 | 功能完备性、正确性、适合性 |
| 性能效率 | 时间特性、资源利用、容量 |
| 兼容性 | 共存性、互操作性 |
| 易用性 | 可辨识、易学、易操作、用户界面美观 |
| 可靠性 | 成熟性、可用性、容错性、易恢复性 |
| 信息安全性 | 保密性、完整性、抗抵赖性、可核查性 |
| 可维护性 | 模块化、可复用、易分析、易修改、易测试 |
| 可移植性 | 适应性、易安装、易替换 |

### 1.3 GB/T 28827.1-2022《信息技术服务 运行维护 第1部分：通用要求》

**适用场景**：运维服务、IT 外包、系统集成后续运维项目。

| 能力要素 | 标书响应要点 |
|---------|-------------|
| 人员 | 运维团队结构、岗位职责、技能要求 |
| 过程 | 服务级别管理、事件管理、问题管理、变更管理、发布管理 |
| 技术 | 运维工具平台、监控告警、自动化运维 |
| 资源 | 运维知识库、备件库、服务台 |

## 二、软件过程改进与能力评估

### 2.1 CMMI（能力成熟度模型集成）

| 等级 | 特征 | 标书响应要点 |
|------|------|-------------|
| CMMI 2级 | 已管理 | 项目计划、配置管理、度量分析 |
| CMMI 3级 | 已定义 | 组织标准过程、培训、同行评审 |
| CMMI 4级 | 量化管理 | 量化项目管理、统计过程控制 |
| CMMI 5级 | 优化级 | 因果分析、持续优化 |

**常见等效替代**：
- CMMI 3级 ≈ SPCA（软件过程能力评估）3级
- CMMI 5级 ≈ ISO/IEC 15504-5（SPICE 5级）

### 2.2 ISO/IEC 12207《系统和软件工程—软件生命周期过程》

| 过程组 | 包含过程 | 标书响应要点 |
|--------|---------|-------------|
| 协议过程 | 采购、供应 | 供应商管理、交付物清单 |
| 项目过程 | 项目管理、风险管理、质量管理 | 项目计划、风险登记册、QA计划 |
| 技术过程 | 需求、设计、实现、集成、验证、确认 | 生命周期各阶段交付物 |
| 组织过程 | 管理、基础设施、改进、人力资源 | 组织级资源保障 |

## 三、信息安全与数据安全标准

### 3.1 GB/T 22239-2019《网络安全等级保护基本要求》

详见 `行业技术标准_软件开发部分.md` 等保章节。补充要点：

| 等级 | 常见招标要求 | 响应策略 |
|------|-------------|---------|
| 等保二级 | 一般政务系统 | 安全通信网络、安全区域边界、安全计算环境 |
| 等保三级 | 重要政务/金融/能源系统 | 增加入侵防范、恶意代码防范、安全审计、数据备份恢复 |
| 等保四级 | 关键信息基础设施 | 可信验证、强制访问控制、异地灾备 |

### 3.2 ISO/IEC 27001:2013《信息安全管理体系》

**适用场景**：所有涉及敏感数据、个人信息、政务数据的软件开发项目。

| 控制域 | 标书响应要点 |
|--------|-------------|
| 安全策略 | 信息安全方针、目标、职责 |
| 信息安全组织 | 安全管理机构、外部相关方管理 |
| 人力资源安全 | 背景审查、保密协议、离职管理 |
| 资产管理 | 信息资产清单、分级保护 |
| 访问控制 | 身份鉴别、权限管理、最小权限原则 |
| 密码学 | 数据加密、密钥管理、数字签名 |
| 物理和环境安全 | 机房安全、介质管理 |
| 运行安全 | 变更管理、容量管理、恶意软件防范 |
| 通信安全 | 网络安全、信息传输安全 |
| 系统获取/开发和维护 | 安全开发生命周期（SDL） |
| 供应商关系 | 供应链安全 |
| 信息安全事件管理 | 事件响应流程 |
| 业务连续性 | 灾难恢复、备份策略 |
| 合规性 | 法律法规符合性 |

### 3.3 GB/T 35273-2020《个人信息安全规范》

| 核心要求 | 标书响应要点 |
|---------|-------------|
| 最小化采集 | 只采集业务必需个人信息 |
| 告知同意 | 隐私政策、弹窗告知、授权机制 |
| 敏感信息保护 | 身份证、手机号、地址等加密存储/脱敏展示 |
| 跨境传输 | 数据出境安全评估/标准合同/认证 |
| PIA评估 | 个人信息保护影响评估流程 |

## 四、IT服务与运维认证

### 4.1 ITSS（信息技术服务标准）

| 等级 | 适用场景 | 等效替代 |
|------|---------|---------|
| ITSS 运行维护一级 | 大型运维项目 | ISO/IEC 20000-1 + 同类业绩 ≥3个 |
| ITSS 运行维护二级 | 中型运维项目 | ISO/IEC 20000-1 |
| ITSS 运行维护三级 | 一般运维项目 | ISO/IEC 20000-1（基本符合） |

### 4.2 ISO/IEC 20000-1《信息技术服务管理》

| 过程域 | 标书响应要点 |
|--------|-------------|
| 服务管理体系 | SMS 范围、方针、目标 |
| 服务设计与转换 | 服务目录、SLA、变更管理 |
| 服务交付 | 服务级别、可用性、容量、连续性 |
| 关系与协议 | 业务关系管理、供应商管理 |
| 资源与过程控制 | 预算、人员、信息安全 |

## 五、软件开发资质等效替代规则

### 5.1 软件开发能力认证

| 原资质要求 | 等效资质 | 替代条件 |
|-----------|---------|---------|
| CMMI 5级 | ISO/IEC 15504-5（SPICE 5级） | 需认证机构认可 |
| CMMI 3级 | ISO/IEC 15504-3（SPICE 3级） | 需认证机构认可 |
| SPCA 3级 | CMMI 3级 | 直接等效 |
| 软件企业认定 | 高新技术企业 | 需软件业务收入占比达标 |

### 5.2 信息安全认证

| 原资质要求 | 等效资质 | 替代条件 |
|-----------|---------|---------|
| 信息安全服务资质一级 | CCRC 信息安全服务资质一级 | 直接等效 |
| 信息安全等级保护测评机构 | 无等效替代 | 公安部核准，不可替代 |
| ISO/IEC 27001 | ISO/IEC 27001:2013 | 认证范围需覆盖项目业务 |

### 5.3 人员证书等效

| 原证书要求 | 等效证书 | 替代条件 |
|-----------|---------|---------|
| PMP | 信息系统项目管理师（高级） | 需软考证书 |
| 系统架构设计师（高级） | TOGAF 9 + 5年架构经验 | 企业架构领域互认 |
| 软件设计师（中级） | 系统分析师（中级） | 设计类岗位部分认可 |
| 信息安全工程师（中级） | CISP | 安全岗位互认 |

## 六、软件开发废标条款模式（补充）

### DQ-S01：软件著作权缺失废标

- **触发关键词**：软件著作权、自主知识产权、源代码所有权
- **表述模式**："投标人须提供本项目涉及软件的著作权证书或知识产权承诺函"
- **严重等级**：fatal
- **响应要点**：准备已有软著证书，或承诺交付后转移著作权

### DQ-S02：等保测评承诺缺失废标

- **触发关键词**：等保测评、等级保护、二级/三级等保
- **表述模式**："投标人须承诺系统上线后通过等级保护 X 级测评"
- **严重等级**：fatal
- **响应要点**：明确等保定级、测评时间节点、责任分工、费用承担

### DQ-S03：关键人员资质不符废标

- **触发关键词**：项目经理、技术负责人、系统架构师、PMP
- **表述模式**："项目经理须具备 PMP/信息系统项目管理师（高级）证书，且有 X 年同类项目经验"
- **严重等级**：fatal
- **响应要点**：证书扫描件、简历、社保缴纳证明、项目经历

### DQ-S04：同类业绩不满足废标

- **触发关键词**：同类项目业绩、合同金额、验收证明
- **表述模式**："投标人近 X 年须具有至少 X 个合同金额 ≥ X 万元的 [政务/医疗/教育] 信息化项目业绩"
- **严重等级**：fatal
- **响应要点**：合同关键页、验收报告、业主证明（需脱敏）

### DQ-S05：源代码交付承诺缺失废标

- **触发关键词**：源代码、技术文档、知识产权归属
- **表述模式**："投标人须承诺项目验收后向甲方交付全部源代码、技术文档及知识产权"
- **严重等级**：fatal
- **响应要点**：明确交付物清单、交付时间、知识产权归属条款

## 七、标书响应常用表述模板

### 7.1 资质章节

```
我公司为高新技术企业，已通过 CMMI 3 级、ISO 9001、ISO/IEC 27001 认证，
持有 ITSS 运行维护三级资质。本项目配备信息系统项目管理师（高级）X 名、PMP X 名、
系统架构设计师 X 名、注册信息安全专业人员（CISP）X 名。
```

### 7.2 技术方案章节

```
本项目遵循 GB/T 8567、GB/T 25000.51、GB/T 22239 等国家标准，
采用安全开发生命周期（SDL）流程，覆盖需求分析、安全设计、安全编码、安全测试、上线运维各阶段。
系统将按照等保 X 级要求进行设计和建设，并承诺上线后 6 个月内通过等保测评。
```

### 7.3 运维服务章节

```
本项目运维服务遵循 GB/T 28827.1 和 ISO/IEC 20000-1 标准，建立 7×24 小时服务台、
事件分级响应机制、SLA 承诺（重大故障 2 小时响应、4 小时恢复）、知识库和备件库。
```
