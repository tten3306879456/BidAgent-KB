## 一、总览：为什么需要本地知识库

### 1.1 一句话说明

标书智能体专家系统需要公司内部数据（资质、人员、业绩、报价、模板、技术方案）才能工作，但这些数据涉及商业机密和个人隐私，**不能上传到云端**。所以我们采用"本地存储 + 按需投喂"的模式——数据存在你们自己的电脑上，流程运行到需要时再临时提供给智能体。

### 1.2 云端 vs 本地的分工

| 维度 | 云端知识库（智能体自动管理） | 本地知识库（你们管理） |
|------|---------------------------|----------------------|
| 里面装什么 | 公开法规、废标条款模式、行业技术标准、报价法规、资质替代规则 | 公司资质证书、员工信息、项目业绩、报价记录、标书模板、技术方案 |
| 谁来维护 | 智能体自动检索，无需人工干预 | 各部门自行录入和维护 |
| 数据在哪 | 腾讯云 ima 知识库 | 你们自己的电脑或公司内网服务器 |
| 安全风险 | 低（都是公开信息） | 完全由你们控制，数据不出本地 |
| 当前状态 | 已搭建完成，5个知识库全部可用 | **需要你们按本指南搭建** |

### 1.3 本地知识库的6个库

| 序号 | 知识库名称 | 主要使用部门 | 数据敏感度 | 包含文件 |
|------|-----------|------------|-----------|---------|
| 1 | 公司资质库 | 投标部/行政部 | 高（证书编号/有效期） | 1个CSV + 证书扫描件 |
| 2 | 人员信息库 | 人事部 | 高（个人隐私PII） | 2个CSV + 简历文档 |
| 3 | 业绩案例库 | 投标部/项目管理部 | 中（合同金额/客户信息） | 1个CSV + 项目文档 |
| 4 | 报价方案库 | 投标部/财务部 | 高（商业机密） | 1个CSV + 成本核算表 |
| 5 | 标书模板库 | 投标部 | 中（公司IP） | 1个CSV + 模板文档 |
| 6 | 技术方案知识库 | 技术部 | 高（核心商业机密） | 4个CSV + 方案文档 |

### 数据流向示意

```
各部门在本地维护数据
    │
    ├── 投标部 → 公司资质库（CSV + 扫描件）
    ├── 人事部 → 人员信息库（CSV + 简历）
    ├── 投标部 → 业绩案例库（CSV + 项目文档）
    ├── 财务部 → 报价方案库（CSV + 成本核算表）
    ├── 投标部 → 标书模板库（CSV + 模板文档）
    └── 技术部 → 技术方案知识库（4个CSV + 方案文档）
         │
         ▼
    标书流程运行时，按需将文件投喂给智能体
         │
         ▼
    智能体接收 → 内存处理 → 输出结果 → 原始数据仍在本地
```

## 三、角色分工矩阵

### 谁负责什么

| 知识库 | 负责部门 | 负责人角色 | 录入人 | 审核人 | 更新频率 |
|--------|---------|-----------|--------|--------|---------|
| 公司资质库 | 投标部/行政部 | 资质管理员 | 行政专员 | 投标部经理 | 获得新资质后1周内 |
| 人员信息库 | 人事部 | HR经理 | HR专员 | 人事总监 | 新员工入职1周内；每半年全员更新 |
| 业绩案例库 | 投标部/项目部 | 投标部经理 | 项目协调员 | 投标部经理 | 项目验收后1个月内 |
| 报价方案库 | 投标部/财务部 | 投标部经理 | 投标专员 | 财务总监 | 每次投标后1周内 |
| 标书模板库 | 投标部 | 投标部经理 | 投标专员 | 投标部经理 | 每次投标后检查更新 |
| 技术方案知识库 | 技术部 | 技术总监 | 架构师/技术经理 | 技术总监 | 每次投标后；新组件研发后 |

### 协作关系

```
投标部 ──→ 发起投标流程，通知各部门准备数据
   │
   ├── 人事部 ──→ 提供人员信息（CSV + 简历）
   ├── 技术部 ──→ 提供技术方案知识库（CSV + 方案文档）
   ├── 财务部 ──→ 提供报价历史（CSV）
   └── 投标部 ──→ 提供资质、业绩、模板（CSV + 文档）
         │
         ▼
    按需投喂给智能体处理
```

## 四、快速启动指南（第一周行动清单）

如果你今天就开始搭建，按以下步骤执行：

### Day 1-2：创建目录 + 启动资质库

```
步骤1：在电脑上创建知识库根目录
       建议路径：D:\标书知识库\（或公司内网共享目录）

步骤2：创建6个子目录
       01_公司资质库\
       02_人员信息库\
       03_业绩案例库\
       04_报价方案库\
       05_标书模板库\
       06_技术方案知识库\
       00_管理文档\

步骤3：把模板文件复制到对应目录
       （模板文件清单见附录）

步骤4：投标部开始录入公司资质清单
       - 收集所有资质证书原件
       - 逐个扫描为PDF
       - 打开 公司资质清单_模板.csv 开始录入
```

### Day 3-5：人事部启动人员信息库

```
步骤5：人事部从HR系统导出全员基本信息
       - 整理为 人员基本信息表.csv
       - 发放技能自评表给全员填写

步骤6：收集核心员工简历
       - 项目经理、技术负责人、架构师等关键角色
       - 按统一模板整理简历
```

### Day 5-7：投标部启动业绩案例库

```
步骤7：盘点近3年的已验收项目
       - 每个项目收集：合同关键页、验收报告、客户证明
       - 扫描为PDF，按项目分文件夹存放

步骤8：录入业绩案例清单.csv
```

> **第一周结束时**，你应该有：
> - 完整的目录结构
> - 公司资质清单.csv（至少录入所有有效资质）
> - 人员基本信息表.csv（至少录入全员基本信息）
> - 业绩案例清单.csv（至少录入近3年主要项目）
>
> 这样就能跑通"招标解析 → 资源匹配 → 商务段编写"的核心流程了。

## 五、六大知识库详细搭建说明

### 5.1 公司资质库

#### 基本信息

| 项目 | 说明 |
|------|------|
| 用途 | 存储公司所有资质证书信息，供智能体匹配投标资质要求 |
| 使用专家 | 资源匹配专家、商务标书专家 |
| 敏感度 | 高（证书编号、有效期属于商业敏感信息） |
| 负责部门 | 投标部/行政部 |
| 预计搭建时间 | 3-5天 |
| 优先级 | P0（必须最先完成） |

#### 目录结构

```
01_公司资质库\
├── 公司资质清单.csv              ← 主数据文件（表格统计）
├── 资质证书扫描件\
│   ├── CMMI3级证书.pdf
│   ├── ISO27001证书.pdf
│   ├── 信息系统集成二级.pdf
│   ├── 营业执照.pdf
│   └── ... （所有证书扫描件，按名称命名）
└── 资质有效期监控.xlsx           ← 临期预警表（可选）
```

#### CSV字段说明 — 公司资质清单.csv

| 序号 | 字段名 | 说明 | 示例 | 必填 |
|------|--------|------|------|------|
| 1 | 资质编号 | 唯一标识，建议Q-001格式 | Q-001 | 是 |
| 2 | 资质名称 | 资质全称（与证书一致） | CMMI3级软件能力成熟度认证 | 是 |
| 3 | 资质类别 | 体系认证/行业资质/营业执照/荣誉奖项 | 体系认证 | 是 |
| 4 | 颁发机构 | 发证单位 | CMMI Institute | 是 |
| 5 | 证书编号 | 证书上的编号（准确录入） | CMMI-ML3-2024-001 | 是 |
| 6 | 等级 | 资质等级，没有填"无" | 3级 | 否 |
| 7 | 颁发日期 | 获证日期（YYYY-MM-DD） | 2024-03-15 | 是 |
| 8 | 有效期至 | 到期日期，长期有效填"长期" | 2027-03-14 | 是 |
| 9 | 状态 | 有效/已过期/续证中 | 有效 | 是 |
| 10 | 适用领域 | 哪些项目类型可用 | 信息化/软件开发 | 是 |
| 11 | 扫描件路径 | 相对于01_公司资质库/的路径 | 资质证书扫描件/CMMI3级证书.pdf | 是 |
| 12 | 备注 | 补充说明 | 续证计划：2027年1月启动 | 否 |

#### 操作步骤

1. **盘点收集**（1-2天）
   - 找行政部要公司资质清单原件
   - 逐个收集证书原件，扫描为PDF
   - 命名规范：`[资质名称].pdf`（如 `CMMI3级证书.pdf`）

2. **录入数据**（1天）
   - 用Excel打开 `公司资质清单_模板.csv`
   - 逐条录入，重点核对：证书编号、有效期、扫描件路径
   - 保存时选择"CSV UTF-8（逗号分隔）"格式

3. **校验检查**（半天）
   - 每条记录的扫描件路径能否正确打开
   - 标记3个月内将到期的资质（在备注列写明）
   - 确认没有遗漏的资质

#### 维护要求

| 事件 | 操作 | 时限 |
|------|------|------|
| 获得新资质 | 录入CSV + 扫描件归档 | 1周内 |
| 资质续证 | 更新状态为"续证中"，完成后更新编号和有效期 | 到期前3个月启动 |
| 资质过期 | 更新状态为"已过期" | 过期后立即 |
| 定期核查 | 检查所有资质有效期 | 每季度1次 |

### 5.2 人员信息库

| 5 | 职级 | 职级/职称 | 高级项目经理/PMP | 是 |
| 6 | 入职日期 | YYYY-MM-DD | 2015-06-01 | 是 |
| 7 | 联系方式 | 手机/邮箱 | 138xxxx / zhangm@xxx.com | 否 |
| 8 | 在职状态 | 在职/离职/休假 | 在职 | 是 |

#### CSV字段说明 — 人员技能矩阵表.csv

> 一个人可以有多行记录（每种技能一行），方便按技能维度检索。

| 序号 | 字段名 | 说明 | 示例 | 必填 |
|------|--------|------|------|------|
| 1 | 工号 | 关联基本信息表 | EMP-001 | 是 |
| 2 | 姓名 | 员工姓名（冗余便于使用） | 张明 | 是 |
| 3 | 技能项 | 技能/技术名称 | Spring Cloud微服务 | 是 |
| 4 | 技能类别 | 技术类/管理类/业务类/语言类 | 技术类 | 是 |
| 5 | 熟练度 | 1了解/2入门/3熟练/4精通/5专家 | 4 | 是 |
| 6 | 证书列表 | 持有的相关证书 | PMP、ACP | 否 |
| 7 | 项目经验数 | 该技能相关的项目数量 | 8 | 是 |
| 8 | 领域标签 | 擅长的业务领域 | 政务信息化/智慧城市 | 是 |
| 9 | 最近使用时间 | 最近一次使用该技能 | 2026-07 | 否 |

#### 操作步骤

1. **信息采集**（1周）
   - HR从人事系统导出全员基本信息
   - 制作技能自评表（可用技能矩阵CSV模板），发给全员填写
   - 收集核心员工（项目经理、技术负责人、架构师）的证书扫描件

2. **数据整理**（3-5天）
   - HR整理基本信息表CSV
   - 汇总技能自评数据，整理为技能矩阵CSV
   - 安排核心员工按模板更新简历

3. **证书归档**（2-3天）
   - 证书扫描件按类型分类存放
   - 在基本信息表备注列标注持证情况

#### 维护要求

| 事件 | 操作 | 时限 |
|------|------|------|
| 新员工入职 | 录入基本信息 + 技能矩阵 | 1周内 |

| 13 | 适用场景 | 适用范围 | 所有技术标书 | 否 |
| 14 | 备注 | 标注 | 标杆案例/失分案例 | 否 |

#### 操作步骤

1. **历史方案盘点**（2-3周，技术部主导）
   - 收集近3-5年所有投标的技术方案文档
   - 按项目类型和技术架构分类
   - 提取每个方案核心信息，录入 `技术方案资产库.csv`
   - 标注可复用程度和可复用模块

2. **组件库梳理**（2-3周，各技术团队协同）
   - 盘点公司自研的通用技术组件/模块
   - 评估每个组件成熟度（研发中/试运行/生产级）
   - 录入 `技术组件库.csv`
   - 标注组件间依赖关系

3. **解决方案模式提炼**（1-2周，架构师主导）
   - 从历史方案中提炼可复用的解决方案模式
   - 按业务场景分类
   - 录入 `解决方案模式库.csv`

4. **评分反馈整理**（1周，投标部+技术部协同）
   - 收集历史标书的评分反馈
   - 按评分项类型分类录入 `技术评分要素库.csv`
   - 重点标注失分项和改进建议

> **提示**：4个子库可以分批建设。优先建资产库和组件库（直接影响技术方案设计质量），模式库和评分库可以后续逐步完善。

## 六、智能体数据投喂协议

### 什么是"投喂"？

智能体不直接访问你们本地的数据文件。当标书流程运行到需要本地数据的环节时，你们把对应的CSV文件或文档上传给智能体，智能体在内存中处理后输出结果，原始数据始终留在你们本地。

### 各环节投喂清单

#### 环节1：资源匹配

| 触发时机 | 招标解析和审核完成后 |
|---------|-------------------|
| 需要的文件 | ① 公司资质清单.csv ② 人员基本信息表.csv ③ 人员技能矩阵表.csv ④ 业绩案例清单.csv |
| 投喂方式 | 上传CSV文件，或直接粘贴CSV内容到对话中 |
| 智能体行为 | 资源匹配专家在内存中处理匹配逻辑，输出：资质匹配报告 + 团队推荐名单 + 业绩推荐 |

#### 环节2：商务段编写

| 触发时机 | 资源匹配完成后 |
|---------|-------------|
| 需要的文件 | ① 标书模板文件（从05_标书模板库选取） ② 报价历史记录.csv ③ 成本核算模板.xlsx |
| 投喂方式 | 上传文件给智能体 |
| 智能体行为 | 商务标书专家按模板结构编写商务标书，输出：商务标书初稿 |

#### 环节3：技术段设计

| 触发时机 | 商务段编写完成后（可并行启动） |
|---------|--------------------------|
| 需要的文件 | ① 技术方案资产库.csv ② 技术组件库.csv ③ 解决方案模式库.csv ④ 技术评分要素库.csv ⑤ 相关历史方案文档（如有） |
| 投喂方式 | 上传4个CSV + 相关方案文档 |
| 智能体行为 | 技术方案架构师匹配方案模式+选用组件+参考评分要素优化 → 输出技术总体方案设计书 |

#### 环节4：全文审核

| 触发时机 | 商务标书和技术标书定稿后 |
|---------|----------------------|
| 需要的文件 | 无额外文件（审核依据来自招标文件和云端法规库） |
| 投喂方式 | 无需操作 |
| 智能体行为 | 投标文件审核专家自动审核评分覆盖、一致性、格式合规 |

### 投喂操作示例

```
用户：@资源匹配专家 这是招标文件要点清单，请匹配公司资源

资源匹配专家：收到。请提供以下数据文件：
  1. 公司资质清单.csv
  2. 人员基本信息表.csv
  3. 人员技能矩阵表.csv
  4. 业绩案例清单.csv

用户：[上传4个CSV文件]

资源匹配专家：数据已接收，正在匹配...
  [处理完成后输出匹配报告]
  ⚠ 您的数据仅在本次会话中使用，不会存储到云端。
```

## 七、数据安全红线

### 7.1 五条不可逾越的红线

| 编号 | 红线 | 说明 |
|------|------|------|
| 1 | 数据不出本地 | 所有CSV和文档存储在本地电脑或公司内网，不上传到任何云端服务 |
| 2 | 按需投喂 | 只在标书流程需要时，将相关文件临时提供给智能体 |
| 3 | 敏感数据脱敏 | 投喂前可对身份证号、银行账号等做脱敏处理 |
| 4 | 权限管控 | 知识库目录设置访问权限，仅授权人员可访问 |
| 5 | 定期备份 | 每周备份到外部存储或公司内网服务器 |

### 7.2 各库敏感度分级

| 知识库 | 敏感度 | 敏感数据类型 | 保护措施 |
|--------|--------|------------|---------|
| 公司资质库 | 高 | 证书编号、有效期 | 路径权限管控，定期核查 |
| 人员信息库 | 高 | 姓名、身份证、联系方式、薪资 | PII数据脱敏后投喂 |
| 业绩案例库 | 中 | 合同金额、客户信息 | 按可公开程度分级标注 |
| 报价方案库 | 高 | 报价策略、成本核算、利润率 | 仅投标部和财务部可访问 |
| 标书模板库 | 中 | 公司模板格式、章节结构 | 按需提供，不批量外传 |
| 技术方案知识库 | 最高 | 架构设计、技术选型、组件细节 | 严禁上传云端，仅技术部内部使用 |

### 7.3 投喂时的脱敏建议

| 数据类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 身份证号 | 用****替换中间8位 | 110108********1234 |
| 手机号 | 用****替换中间4位 | 138****5678 |
| 银行账号 | 仅保留后4位 | ************1234 |
| 具体薪资 | 替换为区间 | 15-20K/月 |
| 证书编号 | 仅标注"已验证" | 已验证（详见附件） |

> 智能体在处理Tier 4高敏感数据（资源匹配、商务标书）时，已内置数据安全红线条款：PII数据自动脱敏输出、报价金额不显示具体值、证书编号仅标注"已验证"。

## 十、常见问题（FAQ）

### Q1：CSV文件用什么软件编辑？

**A**：用 Excel 或 WPS 表格打开即可编辑。保存时选择"CSV UTF-8（逗号分隔）"格式。不要保存为 .xlsx 格式。

### Q2：投喂给智能体的数据会被存储吗？

**A**：不会。智能体在处理完成后，原始数据不会存储到云端。下次使用需要重新投喂。所有专家的Prompt中均内置了"不存储到云端"的条款。

### Q3：如果不搭建技术方案知识库会怎样？

**A**：技术方案架构师仍能工作，但只能基于招标文件要求独立设计，无法参考历史方案和复用组件。建议至少先建资产库和组件库，其余后续完善。

### Q4：人员信息库中的敏感信息怎么处理？

**A**：投喂给智能体前，可以对身份证号、手机号等做脱敏处理（用****替换）。智能体处理Tier 4数据时也会自动脱敏输出——姓名/岗位/证书名称保留，身份证/联系方式/薪资脱敏。

### Q5：历史项目文档找不全怎么办？

**A**：至少保证有合同关键页和验收报告。如果缺少技术方案文档，在CSV对应字段留空或标注"缺失"即可。后续逐步补充。

### Q6：多个项目同时投标时，知识库怎么用？

**A**：知识库是共享的，每次投喂时提供同一份数据文件即可。智能体会根据不同项目的要点清单分别处理。

### Q7：技术方案知识库需要所有人都能访问吗？

**A**：不需要。技术方案知识库属于核心商业机密，建议仅技术部内部访问。投标流程需要时，由技术部指定人员提供相关CSV和文档。

### Q8：CSV文件中有中文，打开后乱码怎么办？

**A**：用Excel打开CSV时，选择"数据 → 从文本/CSV"，在编码选项中选择"UTF-8"，然后加载即可。

### Q9：能不能用Excel的xlsx格式代替CSV？

**A**：建议使用CSV格式，因为智能体解析CSV更稳定。如果数据量较大或需要复杂公式，可以用xlsx编辑，最后另存为CSV UTF-8格式。

### Q10：搭建到什么程度可以开始使用智能体？

**A**：完成P0级别的公司资质库和人员信息库后，就可以跑通"招标解析 → 资源匹配 → 商务段编写"的核心流程。其他库可以边用边补。
