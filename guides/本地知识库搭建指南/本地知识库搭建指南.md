# 标书系统本地知识库搭建指南

> 版本: v1.0 | 日期: 2026-08-10 | 适用对象: 标书系统管理员/投标专员

---

## 一、架构总览

### 1.1 设计原则

本系统采用**混合知识库架构**，核心原则是：

```
公开知识 → 云端存储，智能体直接检索
敏感数据 → 本地存储，用户自主管理，按需提供给智能体
```

| 维度 | 云端知识库（智能体管理） | 本地知识库（用户管理） |
|------|------------------------|----------------------|
| **存储位置** | ima 云端（腾讯云） | 用户本地电脑/公司服务器 |
| **管理方式** | 智能体通过 ima-mcp 自动写入和检索 | 用户自行维护，定期更新 |
| **数据特点** | 公开信息、经验总结、不涉及商业机密 | 公司内部数据、涉及商业敏感信息 |
| **访问方式** | 智能体自动检索 | 用户在运行标书流程时，将数据文件提供给智能体 |
| **安全风险** | 低 | 用户完全可控 |

### 1.3 智能体如何使用本地数据

智能体**不直接访问**本地知识库，而是采用**"用户投喂"模式**：

```
用户在本地维护数据（Excel/CSV/文档）
         ↓
标书流程运行到需要本地数据的环节时
         ↓
用户将相关数据文件上传/粘贴给智能体
         ↓
智能体接收数据作为输入参数进行处理
         ↓
处理完成后，结果输出给用户，原始数据仍在本地
```

**具体来说：**

| 标书流程环节 | 需要的本地数据 | 用户操作 |
|-------------|--------------|---------|
| 资源匹配 | 公司资质库 + 人员信息库 + 业绩案例库 | 上传这3个Excel文件给智能体 |
| 商务段编写 | 资源匹配结果 + 标书模板库 + 报价方案库 | 上传模板文件和报价历史 |
| 技术段设计 | 技术方案知识库（方案资产+组件库+模式库+评分要素） | 上传相关CSV文件和参考方案文档 |
| 全文审核 | 无（审核依据来自招标文件和云端法规库） | 无需额外提供 |

## 三、各知识库详细搭建指南

### 3.1 公司资质库

#### 用途
存储公司所有资质证书信息，供资源匹配专家和商务标书专家使用。

#### 包含内容

**表格统计 — 公司资质清单.csv**

| 字段名 | 说明 | 示例 | 必填 |
|--------|------|------|------|
| 资质编号 | 唯一标识 | Q-001 | 是 |
| 资质名称 | 资质全称 | CMMI3级软件能力成熟度认证 | 是 |
| 资质类别 | 分类型 | 体系认证/行业资质/营业执照/荣誉奖项 | 是 |
| 颁发机构 | 发证单位 | CMMI Institute | 是 |
| 证书编号 | 证书上的编号 | CMMI-ML3-2024-001 | 是 |
| 等级 | 资质等级（如有） | 3级 | 否 |
| 颁发日期 | 获证日期 | 2024-03-15 | 是 |
| 有效期至 | 到期日期 | 2027-03-14 | 是 |
| 状态 | 有效/已过期/续证中 | 有效 | 是 |
| 适用领域 | 哪些项目类型可用 | 信息化/软件开发 | 是 |
| 扫描件路径 | 文件相对路径 | 资质证书扫描件/CMMI3级证书.pdf | 是 |
| 备注 | 补充说明 | 续证计划：2027年1月启动 | 否 |

**参考资料 — 资质证书扫描件**

- 所有证书的 PDF 扫描件，按资质名称命名
- 确保扫描件清晰可读，关键信息（编号、有效期、公章）完整
- 建议同时保留原件复印件

#### 搭建步骤

1. **盘点阶段**（建议1-2天）
   - 收集公司所有资质证书原件
   - 逐个扫描为 PDF，命名规范：`[资质名称]_[证书编号].pdf`
   - 按类别整理到 `资质证书扫描件/` 目录

2. **录入阶段**（建议1天）
   - 打开 `公司资质清单.csv` 模板
   - 逐条录入资质信息，确保证书编号和有效期准确
   - 扫描件路径填写相对于 `01_公司资质库/` 的路径

3. **校验阶段**（半天）
   - 检查是否有遗漏的资质
   - 核对每条记录的扫描件路径是否正确（能否打开）
   - 检查有效期，标记3个月内将到期的资质

4. **维护机制**
   - 新增资质：获得新证书后1周内入库
   - 资质续证：到期前3个月启动续证流程
   - 定期核查：每季度检查一次有效期

#### 包含内容

| 部门 | 所属部门 | 技术中心 | 是 |
| 岗位 | 当前岗位 | 项目经理 | 是 |
| 职级 | 职级/职称 | 高级项目经理/PMP | 是 |
| 入职日期 | 入职时间 | 2015-06-01 | 是 |
| 联系方式 | 手机/邮箱 | 138xxxx / zhangm@xxx.com | 否 |
| 在职状态 | 在职/离职/休假 | 在职 | 是 |
| 当前项目 | 正在参与的项目 | XX市智慧城市项目 | 否 |
| 可投入时间 | 可用于新项目的时间比例 | 2026-10起可100%投入 | 否 |
| 备注 | 特殊技能/限制 | 持有一级建造师证书 | 否 |

**表格统计2 — 人员技能矩阵表.csv**

| 字段名 | 说明 | 示例 | 必填 |
|--------|------|------|------|
| 工号 | 关联人员基本信息表 | EMP-001 | 是 |
| 姓名 | 员工姓名（冗余，便于使用） | 张明 | 是 |
| 技能项 | 技能/技术名称 | Spring Cloud微服务 | 是 |
| 技能类别 | 技术类/管理类/业务类/语言类 | 技术类 | 是 |
| 熟练度 | 1-5分（1了解/2入门/3熟练/4精通/5专家） | 4 | 是 |
| 证书列表 | 持有的相关证书 | PMP、ACP | 否 |
| 项目经验数 | 该技能相关的项目数量 | 8 | 是 |
| 领域标签 | 擅长的业务领域 | 政务信息化/智慧城市 | 是 |
| 最近使用时间 | 最近一次使用该技能 | 2026-07 | 否 |

> 一人可有多行记录（每种技能一行），这样技能矩阵可以按技能维度检索和筛选。

**参考资料 — 人员简历**

- 每位核心员工（项目经理、技术负责人、架构师等关键角色）准备一份标准格式简历
- 简历模板统一使用 `人员简历模板.docx`，确保格式一致
- 简历内容至少包含：基本信息、教育背景、工作经历、项目经验、技能证书、自我评价
- 存放路径：`02_人员信息库/人员简历库/[姓名]_[岗位]_简历.docx`

#### 搭建步骤

1. **信息采集**（建议1-2周）
   - 从HR系统导出全员基本信息
   - 发放技能自评表，让员工填写技能矩阵（可使用模板）
   - 收集核心员工的证书扫描件

2. **数据整理**（建议3-5天）
   - 将HR数据整理为 `人员基本信息表.csv`
   - 将技能自评数据整理为 `人员技能矩阵表.csv`
   - 安排核心员工按模板更新简历，存入 `人员简历库/`

3. **证书归档**（建议2-3天）
   - 将收集到的证书扫描件按类型分类
   - 存入 `证书扫描件/[证书类型]/` 目录
   - 在人员基本信息表的备注列标注持证情况

4. **维护机制**
   - 新员工入职：1周内录入信息库和技能矩阵
   - 员工离职：状态改为"离职"，保留历史数据（可能再次合作）
   - 技能更新：每半年组织一次技能矩阵更新
   - 简历更新：每次项目结束后更新简历中的项目经验部分

#### 搭建步骤

   - 梳理近3-5年所有已验收项目
   - 按项目类型和技术类型分类
   - 确定哪些项目可以作为投标业绩使用（合同条款是否允许公开）

2. **文档收集**（建议2-3周）
   - 逐个项目收集：合同关键页、验收报告、客户证明
   - 合同关键页通常包括：首页（含双方信息）、金额页、范围页、签字盖章页
   - 验收报告需包含甲方盖章确认
   - 如果有获奖证书、推荐信等也一并收集

## 四、数据提供方式（智能体交互协议）

当标书流程运行到需要本地数据的环节时，用户需要将数据提供给智能体。以下是各环节的数据提供方式：

### 4.1 资源匹配环节

**触发时机**：招标解析专家和标书审核专家完成要点清单后

**用户操作**：
1. 打开本地的 `公司资质清单.csv`、`人员基本信息表.csv`、`人员技能矩阵表.csv`、`业绩案例清单.csv`
2. 将这4个文件上传给智能体（或直接粘贴CSV内容到对话中）
3. 如果需要具体证书扫描件或简历，根据智能体要求提供

**智能体行为**：
- 资源匹配专家接收这些数据作为输入
- 在内存中处理匹配逻辑（不存储到云端）
- 输出：资质匹配报告 + 团队推荐名单 + 业绩案例推荐

### 4.2 商务段编写环节

**触发时机**：资源匹配完成后

**用户操作**：
1. 提供资源匹配专家输出的匹配报告（智能体已有）
2. 上传对应的标书模板文件（从 `05_标书模板库/` 中选取）
3. 如有报价需求，上传 `报价历史记录.csv` 和 `成本核算模板.xlsx`

**智能体行为**：
- 商务标书专家接收模板和数据
- 按模板结构编写商务标书内容
- 输出：商务标书初稿

### 4.3 技术段设计环节

**触发时机**：商务段编写完成后（可并行）

**用户操作**：
1. 上传 `技术方案资产库.csv` — 供架构师参考历史方案
2. 上传 `技术组件库.csv` — 供架构师选用可复用组件
3. 上传 `解决方案模式库.csv` — 供架构师匹配场景化模式
4. 上传 `技术评分要素库.csv` — 供架构师优化评分薄弱环节
5. 如有高度相关的历史方案，上传对应方案文档（`06_技术方案知识库/方案文档/[相关方案].docx`）

**智能体行为**：
- 技术方案架构师接收技术规格要求和参考方案资产
- 匹配最相关的解决方案模式，选用合适的技术组件
- 参考评分要素库优化评分薄弱环节
- 输出：技术总体方案设计书（含组件选用说明）
- 技术标书编写专家基于架构师方案+组件文档编写细节内容
- 技术方案审核专家参考评分要素库预估得分

## 六、数据安全注意事项

1. **数据不出本地**：所有本地知识库的数据文件存储在用户自己的电脑或公司服务器上，不上传到云端
2. **按需提供**：只有在标书流程运行到需要数据的环节时，才将相关文件提供给智能体处理
3. **脱敏处理**：如果担心数据泄露，可以在提供给智能体前对敏感字段（如联系方式、身份证号）做脱敏处理
4. **权限管控**：本地知识库目录建议设置访问权限，仅授权人员可访问
5. **定期备份**：建议每周备份一次本地知识库到外部存储或公司内网服务器
6. **版本管理**：重要的数据变更（如人员离职、资质过期）建议记录变更日志
