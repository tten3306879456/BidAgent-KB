### 1.2 两种知识库的区别

| 维度 | 云端知识库(ima) | 本地知识库 |
|------|----------------|-----------|
| 里面装什么 | 公开法规、行业标准、废标模式 | 公司资质、员工信息、项目业绩、报价记录、标书模板、技术方案 |
| 谁来维护 | 智能体自动检索 + 管理脚本辅助上传 | 各部门自行录入维护 |
| 数据在哪 | 腾讯云 ima 知识库 | 本地电脑或公司内网 |
| 智能体怎么用 | 自动检索，无需人工干预 | 用户在流程运行时上传CSV投喂 |
| 安全风险 | 低（都是公开信息） | 完全由用户控制，数据不出本地 |

### 1.3 各部门职责

| 部门 | 负责的知识库 | 工作内容 |
|------|------------|---------|
| 管理层/IT | 全部 | 目录搭建、脚本部署、权限管理 |
| 投标部 | ④报价方案库 ⑤标书模板库 | 录入报价记录、维护标书模板 |
| 技术部 | ③业绩案例库 ⑥技术方案库 | 录入项目业绩、整理技术方案 |
| 人事部 | ②人员信息库 | 录入员工信息、更新技能矩阵 |
| 资质管理 | ①公司资质库 | 录入公司资质证书、跟踪有效期 |
| 全员 | 云端知识库 | 有新法规/标准时交给维护人员上传 |

### 2.4 可以不用 D 盘吗？

可以。目录路径在 `kb_config.json` 中配置，你可以选择任意位置：

| 方案 | 路径 | 适合场景 |
|------|------|---------|
| 项目内目录 | `./kb_data` | 个人电脑，推荐 |
| 项目目录下 | `C:\Users\xxx\WorkBuddy\项目\知识库` | 跟项目走 |
| 公司内网服务器 | `\\server\share\kb_data` | 多人共享 |

> 只需修改 `kb_config.json` 中的 `base_path` 即可。

### 3.3 .md 种子文件 vs PDF 原文的关系

```
.md 种子文件 = "精华笔记"（人工提炼的要点 + 标书响应建议）
PDF 原文     = "教科书原文"（完整法规/标准条文）

两者互补：智能体搜索时都会命中
├── 想知道"这个标准适用于什么场景" → 命中 .md 摘要
└── 想知道"第7.5.1条具体怎么规定的" → 命中 PDF 原文
```

### 3.4 如何上传新法规/标准到 ima

**场景**：获取了一份新的法规PDF，想添加到云端知识库。

```
操作步骤：

1. 把PDF放到 "03_待上传\" 目录

2. 运行自动索引脚本（提取摘要、更新.md种子文件）：
   python kb_auto_index.py "./kb_data\03_待上传\XXX标准.pdf"

3. 检查脚本输出的摘要是否正确（如有误可手动编辑.md文件）

4. 让智能体帮你上传PDF到ima知识库：
   在对话中说："帮我把 ./kb_data\03_待上传\XXX标准.pdf 上传到知识库"

5. .md种子文件的更新不急着传，攒着等月度自动同步
```

### 3.5 如何导入网页法规

**场景**：在网上看到一篇法规网页，想导入知识库。

在对话中说：
> "帮我把这个法规导入知识库：https://xxx.gov.cn/..."

智能体会调用 `import_urls` 工具直接导入。

## 四、本地知识库搭建说明

### 4.1 搭建步骤

```
Step 1: 运行初始化脚本创建目录结构
   python kb_init.py "./kb_data"

Step 2: 从 "04_CSV模板\" 复制空白模板到对应目录
   复制 → 重命名 → 去掉"_模板"后缀 → 开始录入数据

Step 3: 按优先级录入数据
   P0: 公司资质库(3-5天) → 人员信息库(1-2周)
   P1: 业绩案例库(2-3周) → 标书模板库(1-2周)
   P1: 技术方案库(4-6周)
   P2: 报价方案库(1周)
```

### 4.2 六个本地知识库详解

#### ① 公司资质库
- **文件**: `01_公司资质库\公司资质清单.csv`
- **维护人**: 资质管理岗
- **字段**: 资质编号、资质名称、资质等级、发证机构、证书编号、有效期、状态、适用范围
- **维护要求**: 证书到期前3个月更新，新增资质后1周内录入
- **投喂时机**: 资源匹配专家运行时

#### ② 人员信息库
- **文件**: `02_人员信息库\人员基本信息表.csv` + `人员技能矩阵表.csv`
- **维护人**: 人事部
- **字段(基本信息)**: 工号、姓名、部门、岗位、职级、联系方式、入职日期、状态
- **字段(技能矩阵)**: 工号、姓名、技能项、熟练度、证书名称、证书编号、项目经验数、可用状态
- **维护要求**: 人员变动后1周内更新，技能/证书变化后及时更新
- **投喂时机**: 资源匹配专家运行时
- **⚠️ 安全**: 含员工PII，仅限授权人员访问，投喂时智能体自动脱敏

#### ③ 业绩案例库
- **文件**: `03_业绩案例库\业绩案例清单.csv`
- **维护人**: 技术部
- **字段**: 案例编号、项目名称、合同金额、客户名称、行业领域、项目类型、开始日期、结束日期、项目角色、技术栈、项目描述、成果指标
- **维护要求**: 项目验收后2周内录入
- **投喂时机**: 资源匹配专家运行时

#### ④ 报价方案库
- **文件**: `04_报价方案库\报价历史记录.csv`
- **维护人**: 投标部
- **字段**: 报价编号、项目名称、招标方式、报价金额、中标金额、中标单位、报价日期、报价策略、利润率、评标方法、价格排名、备注
- **维护要求**: 每次投标后1周内录入
- **投喂时机**: 商务标书专家运行时
- **⚠️ 安全**: 含报价金额，投喂时智能体不显示具体数值

#### ⑤ 标书模板库
- **文件**: `05_标书模板库\标书模板目录.csv` + `模板文件\` 目录下的.docx文件
- **维护人**: 投标部
- **字段**: 模板编号、模板名称、适用项目类型、适用行业、模板文件路径、版本号、最后更新日期、制作人、审核人、使用次数、备注
- **维护要求**: 每季度审查更新，新模板制作后1周内登记

#### ⑥ 技术方案库（核心商业机密）
- **文件**: `06_技术方案库\` 下的4个CSV
- **维护人**: 技术部
- **子库**:

| 子库 | 文件 | 内容 |
|------|------|------|
| 方案资产库 | 技术方案资产库.csv | 历史技术方案的结构化信息 |
| 技术组件库 | 技术组件库.csv | 可复用的技术组件清单 |
| 解决方案模式库 | 解决方案模式库.csv | 场景→方案的匹配模式 |
| 技术评分要素库 | 技术评分要素库.csv | 历史得分要素和优化经验 |

- **投喂时机**: 技术方案架构师/技术标书编写专家/技术方案审核专家运行时
- **🔴 安全红线**: 严禁上传云端，仅限本地存储，投喂时智能体即时处理不持久化

### 4.3 数据投喂协议

智能体不直接访问本地数据库，采用"用户投喂"模式：

```
智能体流程运行到需要本地数据时：

1. 智能体提示："请上传人员信息库CSV"
2. 用户从本地目录复制CSV，发送给智能体
3. 智能体读取数据，用于本次任务
4. 任务完成后，数据不留存（不持久化到云端）

投喂流程：
智能体运行 → "需要人员信息库" → 用户上传CSV → 智能体读取处理 → 输出结果 → 数据不留存
```

**各专家投喂清单**:

| 专家 | 需要投喂的本地库 |
|------|-----------------|
| 招标解析专家 | 无（只用云端知识库） |
| 招标文件审核专家 | 无（只用云端知识库） |
| 资源匹配专家 | ①公司资质库 + ②人员信息库 + ③业绩案例库 |
| 商务标书专家 | ①公司资质库 + ④报价方案库 + ⑤标书模板库 |
| 技术方案架构师 | ⑥技术方案库(全部4个子库) |
| 技术标书编写专家 | ⑥技术方案库(技术组件库 + 技术评分要素库) |
| 技术方案审核专家 | ⑥技术方案库(技术评分要素库 + 方案资产库) |
| 投标文件审核专家 | 无（审核已生成的标书内容） |
| 文档排版专家 | 无（只做排版） |

### 5.4 kb_sync_manager.py — 同步管理

**用途**: 跟踪本地.md种子文件的修改状态，辅助同步到ima。

#### 命令一览

| 命令 | 功能 | 使用场景 |
|------|------|---------|
| `check` | 扫描所有.md的MD5，输出需同步清单 | 月度检查、手动检查 |
| `status` | 表格展示所有文件同步状态 | 快速查看全局 |
| `mark <文件名>` | 标记单个文件已同步 | 上传成功后调用 |
| `mark-all` | 批量标记所有文件已同步 | 初始化基线 |
| `list` | 列出所有跟踪的.md文件 | 查看文件清单 |
| `upload <文件> <凭证>` | 用create_media凭证上传到COS | 同步上传时调用 |

#### 使用示例

```bash
# 检查哪些文件有更新需要同步
python kb_sync_manager.py check

# 查看所有文件状态
python kb_sync_manager.py status

# 上传成功后标记已同步
python kb_sync_manager.py mark "GBZ117等核工业标准.md"

# 初始化：标记所有现有文件已同步
python kb_sync_manager.py mark-all
```

#### 同步状态说明

| 状态 | 含义 | 需要操作 |
|------|------|---------|
| SYNCED | 本地与ima一致 | 无需操作 |
| UPDATED | 本地有修改，待同步 | 需要上传到ima |
| NEW | 新文件，从未同步 | 需要上传到ima |
| MISSING | 文件被删除 | 需要在ima中也删除 |

## 七、月度同步自动化

### 7.1 自动化说明

已创建 WorkBuddy 自动化任务，每月1日自动触发：

```
触发(每月1日) → 运行 check 命令 → 有更新？
  ├─ 有 → 列出文件清单，询问"是否同步？"
  │       ├─ 确认 → 自动上传到ima (create_media → COS上传 → add_knowledge → mark)
  │       └─ "攒着" → 只报告检测结果，不上传
  └─ 无 → 告知"本月无需同步"
```

### 7.2 手动触发同步

不等月度提醒，随时可以手动同步：

```
在对话中说："帮我检查一下知识库有没有需要同步的"

智能体会:
1. 运行 kb_sync_manager.py check
2. 如果有更新，列出文件清单
3. 询问是否上传
4. 确认后自动上传到ima
```

### 7.3 同步后清理旧版

ima不支持原地更新文件，同步后ima中会有新旧两个版本。建议：

```
同步完成后：
1. 登录 https://ima.qq.com
2. 打开「你的知识库」
3. 找到旧版的.md文件，手动删除
4. 保留新版即可
```

## 八、数据安全红线

### 8.1 分级管理

| 级别 | 知识库 | 存储位置 | 能否上传云端 |
|------|--------|---------|------------|
| Tier 1 | 本地标书模板库 | 仅本地 | ❌ 不可 |
| Tier 2 | 标书法规库/标书案例库/投标文件编辑模板库/软件开发标书知识库/核工业标书知识库 | 云端为主 | ✅ 已在云端 |
| Tier 3 | 公司资质库/业绩案例库/报价方案库 | 混合(本地为主) | ❌ 不可 |
| Tier 4 | 人员信息库/技术方案库 | 仅本地 | ❌ 绝对不可 |

### 8.2 红线规则

1. **技术方案库严禁上传云端** — 包含公司核心架构设计、技术选型、解决方案模式
2. **人员信息库严禁上传云端** — 含员工PII（姓名、联系方式、证书编号）
3. **报价金额不显示具体值** — 投喂时智能体自动脱敏
4. **证书编号不输出** — 投喂时智能体仅标注"已验证"
5. **本地数据投喂后不留存** — 智能体即时处理，任务结束即清除

### 8.3 投喂时的自动脱敏

智能体在处理投喂数据时，自动执行以下脱敏规则：

| 数据类型 | 原始格式 | 脱敏后 |
|---------|---------|--------|
| 员工姓名 | 张三 | 张** |
| 联系方式 | 138xxxx1234 | 138****1234 |
| 证书编号 | CERT-2024-001 | 已验证 |
| 报价金额 | 1,250,000元 | 约125万元（模糊化） |

## 九、常见问题（FAQ）

### Q1: 我不是IT人员，能用吗？

可以。日常使用只需要：
- 用Excel打开CSV文件录入数据
- 有新法规PDF时告诉智能体"帮我把这个文件上传到知识库"
- 每月1日自动化提醒时点击确认

脚本运行可以交给IT人员或让智能体代劳。

### Q2: 知识库目录可以放在U盘/移动硬盘吗？

可以，但不推荐。目录路径在 `kb_config.json` 中配置，理论上任何位置都可以。但U盘可能丢失，建议放在固定磁盘或公司内网。

### Q3: 多人可以共用一个知识库目录吗？

可以。把目录放在公司内网共享文件夹（如 `\\server\share\kb_data`），各部门各自维护自己的CSV文件。注意同时编辑同一文件的冲突问题。

### Q4: 智能体能直接读取我的本地CSV吗？

不能。智能体采用"用户投喂"模式——流程运行到需要数据时，智能体提示你上传对应CSV，你把文件发给智能体，它即时处理后不留存。

### Q5: 上传到ima的PDF和.md种子文件有什么关系？

- PDF = 完整原文，权威性强
- .md种子文件 = 人工提炼的要点摘要，含标书响应建议
- 搜索时两者都会被命中，互补关系
- 每上传一个PDF，索引脚本自动往.md追加摘要条目

### Q6: .md种子文件更新后必须马上同步到ima吗？

不需要。.md在本地维护，积累一批后等月度自动同步即可。PDF原文每次必须传ima。

### Q7: 智能体搜索知识库时会不会搜到旧版本？

ima不支持原地更新，同步后会有新旧两版。建议同步后去ima.qq.com删除旧版.md。

### Q8: 技术方案库为什么不能传云端？

技术方案包含公司核心架构设计、技术选型、可复用组件、解决方案模式，是公司核心商业机密。上传云端有泄露风险，且很多政企合同明确要求不得上传第三方平台。

### Q9: 如果公司没有人事部，人员信息库谁维护？

投标负责人兼任即可。人员信息库的核心用途是：投标时匹配项目人员要求，需要知道谁有什么证书、谁有空、谁做过类似项目。不要求非常完整，但关键信息（证书、技能、项目经验）要有。

### Q10: 如何查看当前知识库的完整状态？

```bash
# 查看云端知识库文件状态
在对话中说："查看一下知识库里的文件列表"

# 查看本地.md同步状态
python kb_sync_manager.py status

# 检查哪些.md需要同步
python kb_sync_manager.py check
```
