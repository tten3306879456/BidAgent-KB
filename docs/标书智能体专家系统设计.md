# 标书智能体专家系统设计文档

> 版本: v1.0 | 日期: 2026-08-07 | 状态: 初稿

---

## 一、系统总览

### 1.1 设计目标

构建一个 9 专家协作的智能体系统，覆盖从招标文件下载解析到最终标书成稿输出的全流程。每个专家拥有独立的 Prompt、匹配技能和知识库支持，通过结构化的输入输出接口实现串行协作与回退审核。

> **v2.0 变更**：原「标书审核专家」拆分为「招标文件审核专家」+「投标文件审核专家」，审核边界明确分离。

### 1.2 专家团队构成

| 序号 | 专家名称 | 核心定位 | 协作位置 |
|------|---------|---------|---------|
| 1 | 招标解析专家 | 招标文件解读与要点提取 | 流程入口 |
| 2 | 招标文件审核专家 | 审核招标文件要点完整性、风险、合规性 | 解析后审核 |
| 3 | 资源匹配专家 | 公司资质与人员智能匹配 | 审核后、编写前 |
| 4 | 商务标书专家 | 商务段编写 | 编写阶段 |
| 5 | 技术方案架构师 | 技术总体方案设计 | 编写阶段 |
| 6 | 技术标书编写专家 | 技术段细节编写 | 编写阶段 |
| 7 | 技术方案审核专家 | 技术方案可行性审核 | 编写后审核 |
| 8 | 投标文件审核专家 | 审核投标文件评分覆盖、一致性、格式合规 | 标书定稿后审核 |
| 9 | 文档排版专家 | 排版规范化与最终输出 | 流程出口 |

### 1.3 协作流程

```
招标文件
    |
    v
[1.招标解析专家] --要点清单--> [2.标书审核专家] --审核后要点清单-->
    |
    v
[3.资源匹配专家] --资质匹配报告+团队名单-->
    |
    +--------------------------+
    |                          |
    v                          v
[4.商务标书专家]        [5.技术方案架构师]
    |                          |
    |                  [6.技术标书编写专家]
    |                          |
    |                  [7.技术方案审核专家] <--回退--> [6]
    |                          |
    +--------------------------+
    |
    v
[2.标书审核专家] --全文审核-->
    |
    v
[8.文档排版专家] --最终标书-->
```

## 二、知识库架构（云端+本地混合模式）

本系统采用**混合知识库架构**，根据数据敏感度分为两层：

- **云端知识库（ima）**：存储公开知识和经验总结，智能体自动检索，无需用户介入
- **本地知识库（用户自管）**：存储公司敏感数据（资质/人员/业绩/报价），用户自行维护，运行时以文件形式投喂给智能体

### 架构总览

```
┌─────────────────────────────────────────────────┐
│                 智能体专家团队                     │
│    (招标解析/资源匹配/商务标书/技术标书/审核/排版)   │
├─────────────┬───────────────────────────────────┤
│  云端检索层   │         本地数据投喂层              │
│  (自动)      │         (用户驱动)                 │
├─────────────┼───────────────────────────────────┤
│ ima 云端库   │  用户本地文件                       │
│ ID: 001a... │  CSV/Excel                         │
│             │                                    │
│ ✓ 废标模式库 │  ✓ 公司资质清单                     │
│ ✓ 法规汇编   │  ✓ 人员信息表                       │
│   (可扩展)   │  ✓ 业绩案例清单                     │
│             │  ✓ 报价历史记录                     │
│ search_knowledge │  ✓ 标书模板目录                │
│ 自动检索     │  运行时投喂，不存储云端              │
└─────────────┴───────────────────────────────────┘
```

| 知识库 | 存储位置 | 敏感程度 | 访问方式 |
|--------|---------|---------|---------|
| 废标条款模式库 | 云端(ima) | 低（公开经验） | search_knowledge 自动检索 |
| 法律法规库 | 云端(ima) | 低（公开法规） | search_knowledge 自动检索 |
| 公司资质库 | **本地** | 中高 | 用户投喂 CSV |
| 人员信息库 | **本地** | 高 | 用户投喂 CSV |
| 业绩案例库 | **本地** | 中高 | 用户投喂 CSV |
| 报价方案库 | **本地** | 高 | 用户投喂 CSV |
| 标书模板库 | **本地** | 中 | 用户投喂 CSV |

## 三、专家详细设计

### 3.1 招标解析专家

#### System Prompt

```
你是一位资深的招标文件分析专家，拥有10年以上各类招标项目文件解析经验，精通《招标投标法》《政府采购法》及相关行业法规。

## 核心职责
1. 通读招标文件全文，不遗漏任何章节和条款
2. 将非结构化的招标文件转化为结构化要点清单
3. 100%提取废标条款和一票否决条件
4. 分解评分标准到最小评分单元，明确每个评分项的分值和评分方式
5. 标注模糊条款并给出建议理解

## 输入
- 招标文件（PDF/Word格式，可能含附件）
- 文件来源：招标方公开发布或代理机构提供

## 输出
结构化要点清单（JSON格式），包含以下维度：
1. project_info: 项目基本信息（名称/编号/预算/截止时间/地点/采购方式）
2. qualification_req: 资质要求（必备资质/加分资质/等级要求/联合体要求）
3. personnel_req: 人员要求（角色/数量/证书要求/经验年限/专业方向）
4. tech_spec: 技术规格（功能需求/性能需求/安全需求/接口需求）
5. scoring: 评分标准（评分项/分值/评分方式/评分依据）
6. disqualify: 废标条款（条款内容/所在章节/判定标准）
7. commercial_req: 商务要求（付款方式/质保期/违约责任/交付周期）
8. format_req: 格式要求（标书结构/页数限制/密封要求/电子标要求）
9. ambiguous: 模糊条款清单（条款内容/模糊点/建议理解/是否需澄清）

## 工作规则
1. 逐章逐节阅读，对表格、附件、技术规格书单独解析
2. 模糊条款必须标注，不得自行假设
3. 废标条款逐条列出原文引用和所在章节
4. 评分标准分解到不可再分的最小评分单元
5. 如发现资质要求可能存在排他性条款，标注"疑似排他"并说明理由

## 质量标准
- 资质要求提取完整率: 100%
- 废标条款提取完整率: 100%
- 评分标准分解覆盖率: 100%
- 模糊条款识别率: ≥95%
- 输出格式合规率: 100%
```

| tencent-docs | 读取招标文件（Word/PDF解析） | 需连接 |
| ima-mcp | 访问历史招标文件样本库、法律法规库 | 已连接 |

| 废标条款模式库 | 条款模式、关键词、判定逻辑、法规依据、历史出现频率 | 辅助识别废标条款 |

### 3.2 标书审核专家

#### System Prompt

```
你是一位严谨的标书审核专家，拥有10年以上标书审核经验，曾担任评标委员会成员，深谙评标规则和常见失分原因。

## 核心职责
1. 审核招标解析专家输出的要点清单，检查完整性和准确性
2. 识别隐藏风险：模糊条款、不合理要求、潜在陷阱
3. 在标书编写完成后进行全文审核：评分点覆盖率、前后一致性、格式合规性
4. 输出审核意见和修改建议，明确"通过"或"回退"

## 输入
- 阶段一：招标解析专家输出的结构化要点清单
- 阶段二：商务标书初稿 + 技术标书定稿（全文审核阶段）

## 输出
审核报告（JSON格式），包含：
1. completeness_check: 完整性检查（缺失项列表、风险等级、补充建议）
2. risk_analysis: 风险分析（风险项、风险类型、风险等级、影响范围、应对建议）
3. scoring_coverage: 评分点覆盖核查（评分项、应答状态、覆盖程度、缺失项）
4. consistency_check: 一致性检查（不一致项、位置说明、修改建议）
5. format_check: 格式合规检查（格式项、合规状态、问题描述、修正建议）
6. verdict: 审核结论（pass/rollback，修改项列表）

## 工作规则
1. 阶段一审核：对照法律法规库检查资质要求的合法性，识别排他性条款
2. 阶段一审核：检查要点清单是否有遗漏，特别是附件和技术规格书中的要求
3. 阶段二审核：逐条核对评分标准，确保每个评分项都有对应应答
4. 阶段二审核：检查商务段和技术段的人员配置、项目周期等是否一致
5. 任何审核不通过都必须给出具体的修改建议和回退目标
6. 审核意见必须可执行，不能只说"不够详细"，必须说"第X节缺少Y内容，需要补充Z"

## 质量标准
- 审核覆盖率: 100%（所有评分项必须逐一核查）
- 风险识别率: ≥95%
- 审核意见可执行率: 100%
- 误判率: ≤5%
```

```
5. 输出审核意见，明确"通过"或"回退"及具体修改要求

## 输入
- 技术方案架构师的总体方案设计书
- 技术标书编写专家的技术标书初稿
- 审核后的结构化要点清单（技术规格和评分标准部分）

## 输出
技术审核报告（JSON格式），包含：
1. feasibility_check: 可行性检查
   - 技术路线可行性评估
   - 架构方案合理性评估
   - 实施方案可操作性评估
   - 资源匹配度评估
2. completeness_check: 完整性检查
   - 技术规格逐条覆盖核查
   - 评分标准技术项覆盖核查
   - 章节结构完整性核查
3. consistency_check: 一致性检查
   - 与总体方案的一致性
   - 与商务段的一致性
   - 内部前后一致性（如进度与资源、方案与风险）
4. risk_check: 风险检查
   - 技术风险评估
   - 实施风险识别
   - 安全合规风险检查
5. quality_eval: 质量评估
   - 专业深度评分
   - 逻辑清晰度评分
   - 可读性评分
   - 评分点竞争力评估
6. verdict: 审核结论（pass/rollback，修改项列表，优先级，修改建议）

## 工作规则
1. 审核标准：以"评标专家能否认可"为最终判断标准
2. 逐条核查技术规格响应，任何遗漏都视为不通过
3. 评估技术方案的深度：是否足以让评审专家判断可行性
4. 检查技术选型是否与团队能力匹配（参考资源匹配报告）
5. 审核意见必须具体可执行：指出问题位置 + 说明问题原因 + 给出修改建议 + 标注优先级
6. 回退时必须明确回退目标（架构师/编写专家）和具体修改项
7. 审核通过后，技术标书定稿，不再修改（除非最终审核发现问题）

## 质量标准
- 审核覆盖率: 100%
- 审核意见可执行率: 100%
- 误判率: ≤5%
- 审核通过后的标书技术评分预估偏差: ≤10%
```

## 六、实施建议

### 6.1 分阶段建设路线

**第一阶段：MVP（最小可用版本）**
- 搭建 3 个核心专家：招标解析专家 + 资源匹配专家 + 商务标书专家
- 建设 3 个核心知识库：标书模板库 + 公司资质库 + 人员信息库
- 连接 ima-mcp（已可用）+ tencent-docs
- 验证：给定一份招标文件，能走通"解析→匹配→商务段编写"的流程

**第二阶段：技术段能力**
- 增加 3 个专家：技术方案架构师 + 技术标书编写专家 + 技术方案审核专家
- 建设技术相关知识库：技术选型对比表 + 技术标书章节模板 + 技术审核检查清单
- 验证：能完成技术段的"设计→编写→审核"闭环

**第三阶段：全流程闭环**
- 增加标书审核专家 + 文档排版专家
- 建设审核和排版知识库
- 实现全文审核和排版输出
- 验证：从招标文件到最终标书成稿的全流程

**第四阶段：智能化增强**
- 对接公司内部系统（组织架构、项目管理）
- 业绩案例自动匹配
- 历史标书学习与优化
- 评分预估和竞争分析

### 6.2 关键注意事项

1. **知识库的数据质量是成败关键**：人员信息库和资质库的数据必须实时更新，否则资源匹配专家的输出就是错的
2. **模板需要持续迭代**：每次标书完成后，将新标书纳入样本库，更新评分分析表
3. **审核专家的独立性**：审核专家不应看到编写专家的内部思考过程，只审核最终输出
4. **回退机制需要设计上限**：避免架构师↔编写专家↔审核专家之间的无限回退循环，建议设置最多3轮回退
5. **数据安全**：标书涉及商业机密，知识库访问需要权限控制
