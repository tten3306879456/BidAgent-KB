## 五、Prompt 调优后的增量改动

基于测试发现，对 Agent MD 做了以下 6 处调优：

### 5.1 交叉验证规则增强（G001）

原规则1：
> 资质-评分一致性：必备资质是否在评分标准中也有体现？

调优后：
> 资质-评分一致性：检查资质要求与评分标准的双向关系——(a) 必备资质是否同时出现在评分项中（双重影响：不满足废标+满足加分）；(b) 评分标准中出现的资质是否在必备清单中缺失（纯加分资质，建议标注为bonus类型补充到qualification_req）

### 5.2 缺失项检测规则（G002/G003）

新增工作规则：
> 废标条款中引用的概念（如"投标有效期""重大偏离"等）如未在文件其他章节定义具体标准，必须标注为模糊条款，类型为"标准模糊"，风险等级不低于"中"

### 5.3 联合体资质分解（G004）

qualification_req 增加字段：
```json
{
  "consortium": {
    "allowed": true,
    "max_members": 2,
    "lead_requirements": "牵头方须满足全部资质要求(Q005-Q007)",
    "member_requirements": "各方须满足Q001-Q004和Q008"
  }
}
```

### 5.4 评分标准反向提取加分资质（G005）

新增工作规则：
> 从评分标准的评分细则中反向提取加分资质（如ISO20000、ITSS等），补充到qualification_req中，type标注为"bonus"

### 5.5 隐含要求缺失检测（G006）

新增模糊条款识别模式：
> 技术规格中提到对接/集成已有系统但未提供接口文档或技术规范时，标注为"隐含要求缺失"，风险等级不低于"高"

### 5.6 质量自检清单增强

新增自检项：
- [ ] 废标条款中引用的概念是否全部在文件中有定义
- [ ] 评分标准中的加分资质是否已补充到qualification_req
- [ ] 技术规格中的对接/集成需求是否有对应的技术文档
