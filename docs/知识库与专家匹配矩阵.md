## 5. 匹配缺口分析（优化依据）

> ✅ 2026-08-13：本节所列 P0/P1 缺口已全部修复，保留原文用于追溯优化依据。

### 🔴 缺口 1：专家 Prompt 未绑定实际 KB ID —— ✅ 已解决
- 原状：8 个专家的云端检索指令中，知识库 ID 均为占位符 `<YOUR_IMA_KB_ID>`，库名也是旧架构名称（"法律法规库"/"废标条款模式库"/"报价与商务法规库"）
- 与 `kb_config.json` 现有 6 座库名（标书法规库/标书案例库等）**不一致**，用户按 Prompt 配置时可能绑错库
- **影响**：检索可能落到错误知识库或空结果
- **修复**：9 个专家 Prompt 全部替换为 6 座真实 KB ID + 统一库名，占位符清零

### 🔴 缺口 2：三座行业库无路由机制 —— ✅ 已解决
- 原状：软件开发 / 核工业 / 设备采购 三座行业库已建成（共 9 个种子文件），但 9 个专家 prompt 均为**行业无关**设计，没有任何"识别行业 → 路由行业库"的指令
- **影响**：行业库内容（软件标准、核工业标准、设备技术标准）永远不会被检索，等于白建
- **修复**：招标解析专家新增 **Phase 1 强制行业识别**（关键词表 → `industry` 标签），8 个流程专家全部接入**行业标签路由**（行业库优先、通用底座兜底），行业库内容已可被检索命中

### 🟡 缺口 3：云端投标文件编辑模板库未被利用 —— ✅ 已解决
- 原状：云端模板库 4 个文件（通用框架/商务模板/技术模板/偏离表模板）无人检索，专家依赖用户本地投喂的 DOCX 模板
- **影响**：资源浪费；用户没模板时专家无参考
- **修复**：排版专家接入云端投标文件编辑模板库，用户未投喂模板时自动兜底检索

### 🟢 良好项
- 本地 6 库被 9 个专家按需引用，职责清晰
- 标书法规库、标书案例库引用热度高，覆盖废标判定 + 合规验证两大核心场景
- 敏感数据（资质/人员/报价/技术方案）全部限定本地，符合安全设计
