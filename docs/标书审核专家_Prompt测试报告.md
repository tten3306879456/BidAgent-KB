5. 验证本地数据匹配预警
6. 验证审核意见的可执行性
7. 识别 Prompt 不足并调优

### 3.2 发现的 Prompt 不足与调优建议

| 编号 | 问题 | 调优建议 | 优先级 |
|------|------|---------|--------|
| T001 | 完整性检查缺少"附件深度检查"——只检查了附件目录是否提取，未检查附件内容中的技术细节是否提取 | 增加：对附件中的技术规范、系统清单、接口文档等进行深度检查，确保关键技术信息未遗漏 | P0 |
| T002 | 风险等级评定标准不够精确——"投标有效期不足"是废标条款，其模糊性应提升为"高"而非"中" | 增加：当模糊条款直接影响废标条款时，风险等级自动提升一级 | P0 |
| T003 | 合规检查中缺少"保证金比例"的自动计算——需要人工计算保证金占预算的比例再判断 | 增加：自动计算保证金/预算比例，与法规上限2%对比 | P1 |
| T004 | 缺少"主观分占比"的风险阈值——只标注了35%接近30%警戒线，但未明确超过多少需要预警 | 增加：主观分占比>30%时标注为"主观分风险"，>40%时标注为"高风险" | P1 |
| T005 | 本地数据匹配预警缺少"缺口预估"——只提示了需要什么数据，未预估可能的匹配缺口 | 增加：基于要点清单中的资质/人员要求，预估可能的匹配缺口（如"PMP+10年政务经验的人员可能稀缺"） | P2 |
| T006 | 审核结论缺少"时间紧迫度评估"——未评估答疑期是否充足 | 增加：根据投标截止时间计算剩余时间，评估答疑和澄清的时间是否充足 | P2 |

## 四、Prompt 调优实施

基于测试发现，对 Agent MD 做以下调优：

### 4.1 附件深度检查（T001）

在完整性检查表中增加：

```
| 附件深度 | 附件中的技术规范、系统清单、接口文档等关键技术信息是否提取 | 检查每个附件的内容摘要，标注是否有技术细节未提取 |
```

### 4.2 废标关联风险升级（T002）

在风险分析工作规则中增加：

```
当模糊条款直接关联废标条款时（如"投标有效期"对应废标条款D006），风险等级自动提升一级：
- 原"低"→"中"
- 原"中"→"高"
- 原"高"→"高（致命风险）"
```

### 4.3 保证金比例自动计算（T003）

在不合理要求检查中增加：

```
- 投标保证金比例 = 保证金金额 / 预算金额 × 100%
  - >2% → 违规（超出法规上限）
  - =2% → 合规（在上限）
  - <2% → 合规
```

### 4.4 主观分风险阈值（T004）

在评分标准预核查中增加：

```
- 主观分占比 >30% → 标注"主观分风险"，建议加强论述质量
- 主观分占比 >40% → 标注"高风险"，建议增加客观佐证材料
- 主观分占比 >50% → 标注"极高风险"，建议向招标方提出质疑
```

### 4.5 本地数据缺口预估（T005）

在 local_data_needed 中增加 `gap_forecast` 字段：

```json
{
  "personnel_match": {
    "needed": true,
    "requirements": ["项目经理(PMP+10年政务经验)"],
    "gap_forecast": "PMP+10年政务经验的人员可能稀缺，建议准备2-3名候选人",
    "instruction": "请提供人员基本信息表和人员技能矩阵表"
  }
}
```

### 4.6 时间紧迫度评估（T006）

在 Phase 1 审核结论中增加 `time_urgency` 字段：

```json
{
  "time_urgency": {
    "days_until_deadline": 36,
    "clarification_deadline": "通常为投标截止前15天",
    "days_until_clarification": 21,
    "urgency_level": "normal",
    "note": "时间充足，可正常推进答疑和标书编写"
  }
}
```
